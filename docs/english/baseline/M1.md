# M1 — Month-1 Definition

**Period:** 17 September 2026 → 17 October 2026

**Status:** PROPOSED — several decisions still require review and acceptance by the project owner.

This document defines the Month-1 scope. Decisions D01–D06 in the [Decision Log](../master/07_DECISION_LOG.md) have been accepted; D07–D09 remain proposals. The project owner accepted D05/D06 on 20 September 2026.

## 1. Problem to Test

**HYPOTHESIS:** when surveying a technical topic, a researcher may struggle to distinguish among:

- a concept genuinely appearing more often in research activity;
- growth in the total number of documents in the corpus;
- changes in source coverage;
- changes in terminology or naming;
- effects introduced by corpus selection.

Month 1 tests only whether SITES can **describe change within a defined corpus**. M1 does not determine which technology is better and does not predict the future.

## 2. Primary User and Task

**ACCEPTED — D06:** the primary user is a researcher surveying the literature on a technical topic within a defined corpus.

The minimum task is to:

1. select a concept and time range;
2. inspect how the signal changes and understand what it measures;
3. open the evidence behind the result;
4. understand the scope and limits of the conclusion.

This task has not yet been validated with real users. Engineers making technology decisions and general audiences viewing trends remain alternative user groups, not accepted targets.

## 3. Primary Research Question

> Within a corpus of scholarly documents from a specific technical field, are one or two simple signals sufficient to determine whether a concept is appearing more or less often over time, while preserving the ability to inspect the source data and calculation and reproduce the result?

The supporting questions are listed in [Research Questions](../master/02_RESEARCH_QUESTIONS.md).

## 4. Input

**PROPOSED — D07:**

- one technical field;
- one data source;
- no more than 5,000 records;
- no more than 24 completed months of historical data;
- one evaluation case.

The field, data source, start and end dates, and sampling method **have not been selected**.

The analysis corpus must record at least:

- the query or scope definition;
- references to source records;
- the meaning of each timestamp;
- a snapshot or acquisition-time record;
- the minimum fields required by the signal;
- coverage and missingness.

M1 does not assume that scholarly papers are the best evidence source or that the corpus represents the entire field.

## 5. Output

**PROPOSED — D08:** for each concept, the minimum result must include:

- the concept and definition version;
- the corpus, time range, and data cutoff;
- one or two signal values, including units and denominators;
- the rule and threshold version;
- a descriptive conclusion with its reason, or **insufficient evidence**;
- a small set of representative evidence records;
- complete lineage to every observation that contributed to the calculation;
- references to the input, configuration, code, and metric definition required for replay;
- missing data and disclosed limitations.

The labels emerging, growing, stable, and declining are candidates only. An early appearance in the corpus does not prove that a technology had just been created, and a lower count does not prove that it is dying. M1 will not use an opaque composite score.

## 6. Minimum End-to-End Flow

~~~text
define domain/query
→ acquire a bounded corpus
→ preserve observations and provenance
→ normalize the minimum required fields
→ calculate one primary signal
→ produce a result with an evidence bundle
→ query
→ minimal dashboard
→ reproducible demo
~~~

A second signal may be added only when evidence shows that it contributes information the first signal does not provide.

**PROPOSED — D09:** M1 does not require a separate HTTP API or public hosting. Queries may run in the same process as the application. The dashboard needs only one view that exposes the result, its signals, and the supporting evidence.

If the scope remains too large, reduce the corpus, time range, or number of signals before weakening correctness or traceability requirements.

## 7. Outside the M1 Scope

Under D03, M1 excludes:

- forecasting;
- recommendation;
- optimization;
- autonomous agents;
- large-scale distributed infrastructure;
- multiple data sources unless evidence establishes that they are necessary;
- opaque LLM-based trend scoring.

Global entity resolution, a complete graph, production operation, and public deployment are deferred by default. See [Scope and Non-Goals](../master/01_SCOPE_AND_NON_GOALS.md).

## 8. Open Decisions

- **D07:** field, data source, corpus, and time range;
- **D08:** signal formula, labels, thresholds, and evaluation method;
- **D09:** storage, database, framework, query interface, dashboard, deployment, and whether to use ML or LLMs.

D05 evidence/correctness principles and D06 user/task are accepted; their empirical validation remains outstanding. No physical schema or implementation stack has been accepted.

## 9. Hypotheses to Test

| Hypothesis | Test | If false |
| --- | --- | --- |
| A narrow user task still provides value | R8 and the Define/Research Gate | Revise the user or task before design begins |
| One source provides enough fields for the corpus and signal | R3/R7, data sample, and coverage audit | Change the signal or narrow the scope before adding another source |
| The project can prove which data existed at a historical point in time | R4 and availability audit | Describe the work only as retrospective analysis and narrow the claims |
| A deterministic signal captures more than changes in corpus size | R1/R2/R6, control, and sensitivity analysis | Reject the signal; do not lower the standard after seeing the holdout |
| The demo can be replayed within the accepted resource budget | Measure E8 | Reduce scope with approval; do not extrapolate scalability |

## 10. Completion Criteria

M1 requires a working demo by **17 October 2026**. The demo must answer the primary research question with evidence, not documentation alone.

Proposed Definition of Done:

- the required D05–D09 decisions have been accepted;
- the corpus, definitions, and protocol are frozen before the holdout run;
- criteria E1–E8 in the [Evaluation Protocol](../master/06_EVALUATION_PROTOCOL.md) all pass;
- every demo result has complete lineage;
- two independent runs using the same input, configuration, and code produce semantically identical results;
- another reviewer can replay and explain at least one result from the dashboard;
- limitations and negative results are disclosed;
- no BLOCKER or MAJOR issue remains unresolved.

If the temporal evidence is inadequate or the signal fails the frozen threshold, the conclusion must be **M1 NOT PASSED** with a negative finding. The threshold must not be lowered after evaluation.
