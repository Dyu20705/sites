## 3. Components and flow

```text
Externally anchored F1 + approved product evaluation record
  -> verify exact artifacts and runtime profile
  -> validate 598 identities/fields against frozen raw current/v1 entries
  -> immutable normalized work projection
  -> pinned research evaluator, guarded by strict input validation
  -> monthly results + all declared sensitivities + 21 window queries
  -> JSON results, per-work evidence pages, index/table/SVG
  -> output digest index + separate execution/resource record
```

Four small proposed Python modules: `contracts.py` (typed records and invariant checks), `pipeline.py` (artifact verification, strict projection, pinned evaluator adapter, pure query), `render.py` (escaped local HTML/SVG), `__main__.py` (CLI, new output directory, replay comparison, resource report). No plugin registry, generic repository layer or background worker service.

The adapter calls the existing, hash-verified `signal_evaluator.evaluate` for the closed corpus and each already declared variant. It does not invoke `acquire.py` or any network entry point. The current helper defaults missing current-category membership to exclusion; the new strict boundary rejects missing/invalid membership **before** invoking it. The helper is not promoted into a general-purpose importer. Fixed replay results are compared with their existing oracles before any view is marked complete.

Observation bytes remain separate from derived projections/results. Import means verify/read frozen input, not query the provider or change its records. Raw files are copied byte-for-byte only when packaging requires local evidence links.

## 4. Exact v1 logical records and invariants

These are proposed schemas, not an accepted physical database. JSON fields are required unless explicitly nullable. Reject unexpected fields at product boundaries; an input adapter recognizes the existing research schema explicitly. No implicit coercion of strings/bools into integers.

Aliases: `Sha256` = 64 lowercase hexadecimal characters; `WorkId` = exact member of the 598-work F1 register (the arXiv ID regex alone is insufficient); `VersionId = WorkId + "v1"`; `Month` = one of `2019-01`…`2019-06`; `UTC` = parsed timezone-aware instant serialized with `Z`; `LocalPath` = literal forward-slash relative path confined to the package root, with no drive, absolute path, `..`, symlink/junction escape or executable URL. `Rational={numerator:int>=0,denominator:int>0}` stores the unreduced counting pair. Lists of IDs are sorted, unique and referentially complete.

```text
ArtifactRef-v1 {
  path: LocalPath, sha256: Sha256, size_bytes: int>=0,
  origin: "research_source" | "freeze_support" | "product"
}
SourceRef-v1 {
  role: "current" | "v1", artifact: ArtifactRef-v1,
  entry_index: int>=0, entry_id: string, acquired_at: UTC
}
Work-v1 {
```

`entry_index` is **zero-based**, matching the frozen audit's Atom `<entry>` enumeration. Verify both index and full `entry_id`; do not silently search a different entry if they disagree. Raw file hash, text and parsed normalized values must agree. Retain raw dates/IDs in evidence even where the normalized representation uses UTC `Z`. The original current source may name v2+; only the explicit v1 title/event contributes to the primary result.

Projection mappings are explicit: `submitted_v1_at <- published_at`, `updated_current_at <- updated_current`, `current_version <- version_current`, `event_month <- bin`; preserve original `title_v1`, `title_current`, category arrays and both `source_ref` entries. Apply the pinned audit's existing text normalization, with no new lowercasing, stemming or Unicode normalization of titles. Ref roles must agree with their current/v1 slots. Escaped entry excerpts are for display; exact byte identity always belongs to the complete raw artifact, not a reserialized XML subtree.

The admitted real input must exactly equal F1, including all 598 versions and valid current categories containing `cs.SE`; no mutation, omission, extra record, unknown category or conflicting v1 is tolerated. No source ID is synthesized from a title. Duplicate identical observations contribute once; conflicting same-work/v1 observations fail; revisions contribute zero extra works. Nine late IDs remain in the accepted population; ID month never determines event month.

Core fixture behavior preserves the accepted uncertainty contract: unknown/invalid title remains in N, sets n/share null, retains known matches and bounds `[known/N,(known+unknown)/N]`; N=0 gives n=0 and share/bounds null; an invalid event makes all monthly N/n/share/bounds unresolved, with unassigned IDs explicitly listed. In that last state, `denominator_ids` means only known assigned members and must never be displayed as a complete denominator. No guessed time or default category. Mutated real F1 inputs fail hash validation before those synthetic paths; a future real unknown requires a separately versioned research decision.

All accepted real monthly points are DEFINED. Require n≤N, matched IDs a subset of denominator IDs, and sum monthly N=598, sum n=9. Every denominator member opens an evidence bundle, including the 589 nonmatches. No semantic reference label exists in this schema. SYN simulation lives under a separate, clearly labeled research link and never joins real Work IDs.

## 5. Interfaces, deterministic replay and publication

```text
verify_inputs(root, f1_path, expected_f1_sha, evaluation) -> VerifiedInputs
project(inputs) -> tuple[Work-v1, ...]               # sorted by work_id
measure(works, fixed_rule) -> tuple[SignalPoint-v1, ...]
query(monthly, works, concept="fuzzing", start, end) -> QueryResult-v1
evidence(work_id, inputs, works) -> EvidenceBundle-v1
render(all_21_queries, bundles) -> mapping[LocalPath, bytes]
compare(index_a, index_b) -> equal | explicit per-path mismatches
```

`VerifiedInputs` is an internal immutable mapping of exact admitted ArtifactRefs plus the parsed F1/evaluation identities; callers cannot pass arbitrary file lists to `project`. Unknown concept, noncontiguous/invalid range or start>end produces `INVALID_QUERY`; no fallback window. Monthly results remain six fixed UTC bins; pooled windows use **sum(n)/sum(N)**, never a mean of shares. Unknown values propagate. All six sensitivities/diagnostics declared in F1 remain visible and reproduced; no tuning, additional vocabulary or attractive-window selection.

Canonical product JSON: UTF-8, LF, sorted object keys, sorted sets/records, `ensure_ascii=False`, compact separators, `allow_nan=False`, one terminal newline. Reject duplicate JSON keys/nonfinite numeric input. Python's JSON API supports these serialization controls; this is our proposed fixed-runtime serialization contract, not a cross-language canonical-JSON claim. [Primary docs](https://docs.python.org/3.14/library/json.html)

Semantic artifacts contain no wall clock, absolute machine path, resource measurement or reviewer identity. The semantic root digest hashes the sorted `[relative_path,sha256]` pairs for normalized works, all query results, sensitivities and rendered evidence/view files, excluding the index itself, execution logs and evaluation/runtime records. This avoids self-reference; version changes remain explicit. Preserve rational n/N; display percentage with four decimal places using decimal half-even rounding, with n and N always adjacent. Formatting is not a significance threshold. Existing research float outputs remain untouched; compare their n/N/IDs/status and numeric share under the pinned runtime as well as the new rational representation.

`build` refuses an existing destination (including a symlink). Create one new run directory exclusively, write outputs, then write the complete semantic index and `COMPLETE` marker only after verification succeeds. A crash may leave a visibly incomplete run; never replace it or display it as PASS. New runs always use new paths. No claim of atomic directory publication or power-loss durability. `compare` is read-only and refuses incomplete runs. A failed run gets a failure record if it can be written safely; a second attempt uses another directory.

`compare` checks F1 identity, product commit/code hash, schema version, complete artifact path set, per-file bytes and semantic root digest. It reports every mismatch; equal numeric totals alone are insufficient. Reviewer/runtime/execution records are compared and reported separately, because they must differ between genuine author and reviewer runs.

## 7. Failure, null and security boundary

Local, read-only evidence processing; user-chosen fresh output directory only. No listener, authentication service, secret, subprocess command from input data or cloud operation. Input filenames/IDs never become unchecked output paths. Hash and size checks precede parsing; only exact F1 allowlisted raw bytes are admitted. No arbitrary uploaded XML, external entity resolution, template execution or raw HTML from titles. Use `html.escape(..., quote=True)` for displayed source strings and separately validate every link destination; escaping alone does not make a URL safe. [Primary docs](https://docs.python.org/3.14/library/html.html)

Raw provider entry URLs are shown as escaped text. If an optional online paper link is included, construct only `https://arxiv.org/abs/{validated_version_id}`, label it external/optional, and never require it for the offline task. No PDF/full-text bundling; metadata rights do not imply PDF redistribution rights. Logs contain IDs, counts, digest/path failures and timings, not secrets or unrelated local paths.

CLI exits: 0 success, 1 verification/identity/metric/resource failure, 2 invalid arguments or pre-existing output. Error codes include `MANIFEST_DIGEST`, `ARTIFACT_DIGEST`, `RUNTIME_PROFILE`, `IDENTITY_CONFLICT`, `UNKNOWN_CATEGORY`, `RAW_LINEAGE`, `INVALID_QUERY`, `OUTPUT_EXISTS`, `INCOMPLETE_RUN`, `BUDGET_EXCEEDED`, `MEMORY_NOT_MEASURED`. Never repair a digest, switch provider/rule, drop a failed record, turn null into zero or change the freeze automatically.
